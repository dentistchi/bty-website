1. **Run the entire SQL file without edits** in the trusted psql runner (read-only). It returns one

5. **Return the machine report** (per-migration A/D/E, grouped by final authority; `submit_followup`

## R2.6 — what changed, and why a prior result is void

**PostgreSQL 17 is now the release-authority major.** The expected manifest is replayed on 17 because
that is what the live database runs; a PostgreSQL-16 digest cannot authoritatively judge PostgreSQL 17
(every digest-mode effect degrades to `MANUAL`). PostgreSQL 16 remains a compatibility regression only.

**ACL comparison is scoped to migration authority.** Each ACL effect now carries:

| Field | Meaning | Compared? |
|---|---|---|
| `controlledRoles` | the grantees the migration's own GRANT/REVOKE statements control — derived from the tokenized statements and asserted at generation time | **yes** |
| `tuples` | exact `aclexplode` tuples for those grantees | **yes** |
| `environmentTuples` | ACL created by the Supabase environment, outside migration authority | **no** — diagnostic |

For the three audited **tables** the only privilege statement is
`revoke all on public.<t> from anon, public, authenticated;` — there is no table `GRANT` at all, so
authority covers `PUBLIC`/`anon`/`authenticated` and `service_role`'s table privileges are environment
defaults. For **functions**, `service_role` **is** explicitly granted `EXECUTE`, so it stays controlled.
An environment privilege is not migration drift unless it contradicts a privilege the migration
explicitly controlled; an explicitly revoked privilege present live, or a required explicit grant
absent live, is still a real `CONFLICT`.

**Any `live_audit_result.json` exported under an earlier packet (r2.5, r2.6) is not evidence against
this packet** and is rejected at the handshake. Re-run the current generated SQL and re-export.
